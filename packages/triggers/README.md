# @exaix/triggers — Trigger Adapter Layer

The `@exaix/triggers` package translates external signals into canonical
`ExecutionTriggerEnvelope` objects before they enter the ingestion pipeline.
It also contains the ingestion service, policy gate, and idempotency ledger.

---

## Architecture

```text
External signal
      │
      ▼
ITriggerAdapter<TRawInput>        (WebhookAdapter / ScheduleAdapter /
      │                            FilesystemAdapter / CliAdapter /
      │                            InternalEventAdapter)
      │
      ▼
ExecutionTriggerEnvelope          (canonical envelope — @exaix/core/triggers)
      │
      ▼
TriggerIngestionService
  ├─ TriggerPolicyGate            (disposition rules — accept / reject)
  └─ InMemoryIdempotencyLedger    (duplicate suppression per idempotencyKey)
      │
      ▼
RequestProcessor                  (accepted envelopes only)
```

For the end-to-end flow with AGENT_LOGIC annotation, see
`ARCHITECTURE.md#trigger-adapter-layer`.

---

## Adapter Sources

| Source       | Class                  | Raw input type        | Validation                                             |
| ------------ | ---------------------- | --------------------- | ------------------------------------------------------ |
| `webhook`    | `WebhookAdapter`       | `IWebhookInput`       | HMAC-SHA256 signature, payload size ≤ 1 MB             |
| `schedule`   | `ScheduleAdapter`      | `IScheduleInput`      | 5-part cron, no `@`-shortcuts, no shell metacharacters |
| `filesystem` | `FilesystemAdapter`    | `IFilesystemInput`    | `..` traversal check, must resolve inside `allowedDir` |
| `cli`        | `CliAdapter`           | `ICliTriggerInput`    | Required `command` field                               |
| `internal`   | `InternalEventAdapter` | `IInternalEventInput` | Domain event type allow-list                           |

All adapters implement:

```ts
interface ITriggerAdapter<TRawInput> {
  readonly source: TTriggerSource;
  parse(rawInput: TRawInput): Promise<ExecutionTriggerEnvelope>;
}
```

## ExecutionTriggerEnvelope

The canonical envelope produced by every adapter:

```ts
// packages/core/src/triggers/schemas.ts
{
  triggerId:      string;          // UUID (auto-generated by adapter)
  source:         TTriggerSource;  // "webhook" | "schedule" | "filesystem" | …
  action:         string;          // e.g. "start_flow"
  idempotencyKey: string;          // deduplication key (max 255 chars)
  subject:        string;          // human-readable topic
  payload?:       Record<string, …>;
  metadata?:      Record<string, …>;
  occurredAt:     string;          // ISO 8601
}
```

Validated by `ExecutionTriggerEnvelopeSchema` (Zod) — import from
`@exaix/core/triggers`.

## WebhookAdapter — HMAC-SHA256 Setup

```ts
import { WebhookAdapter } from "@exaix/triggers";

const adapter = new WebhookAdapter({
  secret: Deno.env.get("WEBHOOK_SECRET")!, // shared HMAC secret
  signatureHeader: "x-hub-signature-256", // header name sent by the caller
});
```

The adapter performs a **timing-safe** byte-by-byte comparison between the
received signature and the locally computed HMAC-SHA256 of the raw body.
Payload size is capped at `TRIGGER_PAYLOAD_MAX_BYTES` (1 MB, from
`@exaix/core/types`). Requests exceeding this limit are rejected before the
crypto step.

Signature format expected in the header: `sha256=<hex-digest>`.

## ScheduleAdapter — Cron Rules

```ts
import { ScheduleAdapter } from "@exaix/triggers";

const adapter = new ScheduleAdapter();

// Accepted — standard 5-part cron
await adapter.parse({ cronExpression: "0 9 * * 1-5" });

// Rejected — @-shortcuts are not supported
await adapter.parse({ cronExpression: "@daily" }); // throws

// Rejected — 6-part second-precision variant
await adapter.parse({ cronExpression: "0 0 9 * * 1-5" }); // throws

// Rejected — shell metacharacters
await adapter.parse({ cronExpression: "0 9 * * 1; rm -rf /" }); // throws
```

Cron expressions must be exactly 5 whitespace-separated fields. Each field
must match: `*`, `<number>`, `<n>-<m>`, `<n>-<m>/<step>`, `*/<step>`, or
comma-separated combinations of the above.

## FilesystemAdapter — Path Traversal Protection

```ts
import { FilesystemAdapter } from "@exaix/triggers";

const adapter = new FilesystemAdapter({
  allowedDir: "/home/user/project/Workspace",
});

// Accepted — resolves inside allowedDir
await adapter.parse({ path: "/home/user/project/Workspace/requests/req1.yaml" });

// Rejected — path traversal detected
await adapter.parse({ path: "/home/user/project/Workspace/../secrets" }); // throws

// Rejected — resolves outside allowedDir
await adapter.parse({ path: "/etc/passwd" }); // throws
```

The adapter checks for `..` segments before resolution, then resolves the
path with `@std/path`'s `resolve()` and verifies it starts with
`allowedDir + "/"`. Only paths strictly inside the configured directory are
accepted. The optional `kind` field accepts a `FilesystemEventKind` enum
value (`CREATE`, `MODIFY`, `REMOVE`, `ACCESS`); defaults to `CREATE`.

## AdapterRegistry

`AdapterRegistry` provides type-erased dispatch when the trigger source is
determined at runtime:

```ts
import { AdapterRegistry, WebhookAdapter, ScheduleAdapter } from "@exaix/triggers";

const registry = new AdapterRegistry();
registry.register(new WebhookAdapter({ secret: "...", signatureHeader: "x-hub-signature-256" }));
registry.register(new ScheduleAdapter());

// Dispatch by source string
const envelope = await registry.parseRaw("webhook", {
  headers: { "x-hub-signature-256": "sha256=..." },
  body: new Uint8Array([...]),
});
```

Calling `parseRaw` for an unregistered source throws
`UnsupportedTriggerSourceError`.

All external adapters are **opt-in** — the registry starts empty. Only
adapters the operator explicitly registers are active.

## TriggerIngestionService

The ingestion service wires together the policy gate and idempotency ledger:

```ts
import { InMemoryIdempotencyLedger, TriggerIngestionService, TriggerPolicyGate } from "@exaix/triggers";
import { EventLogger } from "@exaix/core";

const service = new TriggerIngestionService({
  policyGate: new TriggerPolicyGate(),
  ledger: new InMemoryIdempotencyLedger(),
  eventLogger,
});

const result = await service.ingest(envelope);
// result.disposition === "accepted" | "rejected"
```

Accepted envelopes emit a `TriggerAccepted` domain event; rejected envelopes
emit `TriggerRejected`. Duplicate idempotency keys are silently dropped
(disposition `"rejected"` with reason `"duplicate"`).
